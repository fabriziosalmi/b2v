# Contributing to b2v

Welcome to b2v!

We appreciate you contributing to our project. Please read this guide to understand how we work on b2v.

## Code of Conduct

Please adhere to our [Code of Conduct](CODE_OF_CONDUCT.md) to ensure a welcoming and inclusive environment for everyone.

## Contributing Guidelines

We welcome contributions from everyone! Here is a general guide on how you can contribute:

### 1. Setup

Before you start, make sure you have the necessary tools installed:

*   **Rust/Cargo:** For Rust components.
*   **Node.js/npm:** For TypeScript components.

Follow the setup instructions in the `docs/guide/getting-started.md` file for detailed environment setup.

### 2. Development Workflow

For new features, bug fixes, or enhancements, please follow these steps:

1.  **Fork** the repository.
2.  **Clone** your fork locally.
3.  Create a new branch for your changes (e.g., `feat/my-new-feature` or `fix/bug-name`).
4.  Make your changes and ensure you follow our coding style guidelines (see `.rustfmt.toml` and TypeScript conventions).
5.  **Run tests:** Ensure all existing tests pass, and add new tests if necessary.
6.  **Commit** your changes with a clear, descriptive message.
7.  **Open a Pull Request (PR):** Open a PR against the `main` branch of the original repository, clearly explaining what your changes do.

### 3. Submitting Pull Requests

*   **Descriptive Titles:** Use clear and concise titles for your PRs.
*   **Detailed Descriptions:** In the PR description, explain *what* you changed and *why*. Reference any relevant issues if applicable.
*   **Screenshots/Examples (if applicable):** For UI or observable changes, include relevant examples.

### 4. Code Review

When submitting a PR, please be prepared to address feedback from reviewers. Feel free to open an issue if you need clarification on a request.
