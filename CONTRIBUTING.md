# Contributing to b2v

We welcome contributions to the b2v project! Please read our guidelines below before submitting any changes.

## How to Contribute

### 1. Setup
Follow the setup instructions in the README or relevant documentation for setting up the development environment.

### 2. Development Workflow
*   **Branching:** Create a new branch for your feature or fix. Use descriptive branch names.
*   **Coding Style:** Adhere to the established coding styles for Rust and TypeScript. Use tools like `rustfmt` and linters where applicable.
*   **Testing:** Ensure all new features or bug fixes are accompanied by sufficient tests that cover the changes. Run existing tests before submitting a PR.

### 3. Submitting Changes (Pull Requests)
*   **Clarity:** Provide clear and detailed descriptions for your pull requests, explaining what changes you made and why.
*   **Review:** Please ensure your changes are reviewed by at least one other team member before submitting a PR.

### 4. Submitting Issues
If you are reporting a bug or suggesting a feature, please open an issue first, and reference that issue in your pull request if applicable.

## Commit Messages
Please use clear and concise commit messages following Conventional Commits:
`type(scope): subject` (e.g., feat(decoder): add new decoding logic, fix(encoder): correct calculation error)

## Documentation
If you find any errors or have suggestions for improving the documentation, please open an issue or submit a PR to update the relevant files.

Thank you for contributing!
